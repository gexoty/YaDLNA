# Установка с нуля через ADB: Mini 2

## Перед началом

Это инструкция для **новой установки**, а не повторного запуска на уже настроенной колонке. На текущей рабочей станции ничего выполнять не нужно. Для обновления — [отдельный гайд](UPDATE-ROLLBACK.md).

Нужны ADB platform-tools на ПК, уже работающий **root ADB** (`uid=0`) и доступ после перезагрузки, Mini 2 с совместимой прошивкой, доверенная локальная сеть без изоляции Wi-Fi-клиентов. Получение root и сохранение ADB-доступа не входят в установку. Одного непривилегированного ADB недостаточно. SSH/Dropbear и Entware не нужны.

Проверенная конфигурация: Mini 2, ARMv7 hardfloat userspace / glibc 2.30 / Quasar 3.21. Другие модели не проверены. Если шаг дал неожиданный результат — остановиться, сохранить вывод и свериться с диагностикой; не выполнять следующие шаги.

В rootfs будут добавлены только `/etc/init.d/S55zbtproxy` и `/etc/init.d/S99zdlna`, а `/usr/share/dbus-1/system-services/org.bluez.service` будет сохранён и переименован в `.disabled`. Последнее необходимо для bt-proxy, чтобы BlueZ не запускался второй раз на системной шине. Содержимое штатных служб, Quasar, ALSA, библиотек и настроек сети не меняется. На время работы bt-proxy штатные Bluetooth-службы переносятся на частную D-Bus-шину.

Механизм init.d/remount соответствует [исходному руководству](https://hackalice.me/start/ssh/#dropbear), но этот комплект не ставит SSH, не отключает OTA и не меняет маркеры ADB.

## 1. Проверить комплект на ПК

PowerShell, из корня YaDLNA:

```powershell
Set-Location D:\ChatGPT_Codex\YaDLNA
python scripts/verify-release.py
```

Каждую команду на ПК проверять перед следующей: для ADB, Python и Docker ожидается `$LASTEXITCODE -eq 0`. Доступ к нескольким устройствам требует явного `adb -s IP:5555`. При ошибке подключения или передачи не переходить к распаковке и установке.

Если вы только что клонировали репозиторий и `dist` ещё нет:

```powershell
python scripts/fetch-bt-proxy.py
python scripts/package.py
python scripts/verify-release.py
```

Команды сборки/загрузки выполняются только на ПК. Скрипт загрузки получает сторонний bt-proxy по закреплённому commit и сверяет SHA-256. В готовом локальном комплекте он уже сохранён; повторное скачивание не требуется. См. THIRD_PARTY.md об условиях upstream.

## 2. Проверить подключение

Заменить пример `192.168.1.120` адресом своей станции; при нескольких ADB-устройствах везде использовать `adb -s IP:5555 ...`.

```powershell
adb connect 192.168.1.120:5555
adb devices
adb shell id
adb shell uname -a
adb shell cat /proc/device-tree/model
adb shell df -h /data
```

Продолжать только при `uid=0`, ожидаемой Mini 2 и достаточном месте (рекомендуется не менее 10 МиБ). После reboot ADB должен оставаться доступным: заранее проверьте ваш существующий способ доступа. ADB может быть подключён и по USB; тогда `adb connect` не требуется.

## 3. Передать архив и снять исходную копию

```powershell
adb shell mkdir -p /data/local/tmp /data/opt
adb pull /usr/share/dbus-1/system-services/org.bluez.service backups/org.bluez.service.original
adb push dist/yadlna-0.1.1-mini2.tar /data/local/tmp/yadlna-0.1.1-mini2.tar
adb shell
```

Дальнейший блок выполняется **внутри ADB shell на колонке**. Если `/data/opt/station-dlna` уже содержит установленную программу, остановиться и открыть гайд обновления. Содержимое распаковывать только из проверенного архива этого комплекта.

```sh
set -eu
test ! -e /data/opt/station-dlna
test ! -L /data/opt/station-dlna
mkdir /data/opt/station-dlna
cd /data/opt/station-dlna
tar -xf /data/local/tmp/yadlna-0.1.1-mini2.tar
sha256sum -c SHA256SUMS
sh ./install-on-station.sh
```

Ожидается успешная проверка всех файлов, `Audio symbols: OK`, затем `Installed. Rootfs remounted ro. No reboot performed.` Предупреждение libasound о version information на проверенной прошивке известно и само по себе не означает сбой; ненулевой код или отсутствие строки успеха требуют остановки. Если команда завершилась с ошибкой, не перезагружать автоматически: установщик мог успеть сделать часть действий; см. откат.

Что делает установщик: проверяет root, файлы и отсутствие конфликтующей установки, проверяет ABI без воспроизведения и изменения громкости; сохраняет BlueZ activation; копирует помощник; кратковременно remount rootfs rw; устанавливает два init-скрипта и переименовывает activation; выполняет sync и возвращает rootfs ro. Запуск установки выводит фактические команды после проверок. При ошибке прекращает работу и пытается вернуть rootfs ro; автоматического отката частичных действий нет.

## 4. Сохранить резервную копию и перезагрузить

Выйти из ADB shell командой `exit`, затем на ПК:

```powershell
adb pull /data/opt/station-dlna/backup/org.bluez.service backups/org.bluez.service.installer-backup
adb reboot
```

После загрузки:

```powershell
adb connect 192.168.1.120:5555
adb shell cat /run/station-dlna/receiver.log
adb shell cat /run/station-btproxy/proxy.log
adb shell ps
adb shell mount
```

В процессах должны быть bt-proxy и station-dlna, в приёмнике — сообщение запуска без постоянных повторов ошибок, `/` снова ro. В кратком журнале помощника stderr намеренно отключён; проверить также наличие `/tmp/btbus/socket` и процессов Bluetooth. Автозапуск уже настроен двумя init.d-файлами: отдельная cron/systemd-служба не нужна.

## 5. Подключить плеер и проверить звук

Открыть Feishin на Windows с DLNA или Symfonium на Android с UPnP; выбрать `Yandex Mini 2 DLNA` в списке устройств вывода. ПК/телефон и колонка должны видеть SSDP multicast; разрешить приложению доступ в частной сети Windows. Не открывать порты в Интернет.

Выбрать трек Navidrome и проверить звук, pause/resume, громкость. Затем произнести «Алиса, пауза», «Алиса, продолжи», «Алиса, громче/тише». Для «дальше» контроллер должен передать следующий URI: приёмник не знает всю очередь приложения автоматически. Затем проверить следующий/предыдущий трек и работу после ещё одной перезагрузки.

Известное ограничение 0.1.1: голосовой переход назад может запустить предыдущий трек без обновления интерфейса обоих клиентов. Синхронный переход назад выполнять кнопкой в приложении; это не исправлено данной установкой.

HTTPS проверяет сертификат и hostname. Если Navidrome использует частный CA, потребуется отдельная осознанная настройка доверенного CA; не отключайте TLS-проверку. Штатный bundle установщик не меняет.

## 6. После установки

Сохранить на ПК архив, исходный BlueZ activation и вывод установки. `backups/` исключён из Git. Временный tar `/data/local/tmp/yadlna-0.1.1-mini2.tar` можно удалить после успешной проверки; основной комплект и backup сохранить.
