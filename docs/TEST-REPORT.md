# Отчёт о проверках YaDLNA 0.1.1

Дата: **27 октября 2026 года**. Устройство: **Яндекс Станция Мини 2**. Источник музыки: **Navidrome, HTTPS**. Итог: слышимое воспроизведение подтверждено владельцем; после исправления получено подтверждение «Да, музыка играет», затем «Все работает просто безупречно».

## Feishin и Symfonium

| Связка | Результат | Основание |
|---|---|---|
| Feishin, Windows → DLNA → Mini 2, Navidrome | Успешная пользовательская проверка связки | Подтверждение владельца работающей конфигурации |
| Symfonium, Android → UPnP → Mini 2, Navidrome | Успешная пользовательская проверка связки | Подтверждение владельца работающей конфигурации |

Это ручная проверка рабочего сценария, а не автоматическая сертификация клиентов. Версии приложений, Windows и Android не зафиксированы. Отдельный журнал каждой кнопки и каждой голосовой фразы для каждого из двух приложений не снимался; такие результаты здесь не приписываются тестам. Для следующих версий используйте матрицу ниже.

### Выявленное ограничение после первоначальной проверки

Владелец сообщил: голосовое переключение вперёд работает, а при переключении назад в **обоих** клиентах слышен предыдущий трек, но интерфейс не обновляется. Поэтому синхронизация очереди при голосовом Previous **не пройдена**. Успешное воспроизведение и стендовый MPRIS Previous не означают успешного обновления интерфейса клиента. По требованию владельца клиенты и внешние мосты не изменяются; исправление этого ограничения в 0.1.1 не заявляется.

При исправлении заменён только бинарник собственного приёмника, сохранена версия 0.1.0, перезапущен только S99zdlna. Не менялись `/etc/asound.conf`, `quasar.cfg`, `maind`, оба init-скрипта, libssl и libcrypto. Громкость во время финальной проверки не менялась. Голосовые фразы после этой замены отдельно автоматически не произносились.

Первопричина прежнего отсутствия звука: отсутствующий GIO TLS backend штатного souphttpsrc. Версия 0.1.1 принимает HTTPS через статическую libcurl и имеющийся OpenSSL. Обхода проверки TLS нет.

## Артефакт и ресурсы

- Приёмник: 322 128 байт.
- SHA-256: `17bc84eaf317b8dedca9db763e8c629e8215a1914b510a61d6915f8e1b427fca`.
- RSS при воспроизведении: 12 812 КиБ, 5 потоков в момент снимка. RSS включает общие библиотеки, не равен добавленной физической памяти всей системы.
- Исходные URL с токенами, музыкальные образцы и копии прошивки в репозиторий не включены.

## Матрица для повторной ручной проверки

Для **каждого** клиента записать его версию и проверить: обнаружение после холодной загрузки; HTTP и HTTPS трек; pause/resume; перемотку; громкость; mute; следующий трек; предыдущий; окончание трека; голосовые команды; обычный ответ Алисы поверх музыки; восстановление после перезапуска. Для Next отдельно отметить наличие SetNextAVTransportURI. Эта матрица — план повторения, не утверждение о выполнении всех пунктов двумя клиентами.

Новый ADB-установщик и упаковка подготовлены на ПК после рабочего развёртывания. Синтаксис и комплектность проверены локально; повторная чистая установка новым установщиком на колонке не выполнялась, поскольку текущая задача не требует менять работающее устройство.

## Проверки при оформлении репозитория

На ПК повторно выполнены: сборка приёмника с 15 host-тестами, 15 тестов ARM в QEMU и 15 тестов AddressSanitizer/UBSan (leak detection отключён скриптом). Все прошли. Пересобранный ARM-файл совпал по SHA-256 с сохранённым релизом и установленным ранее бинарником. Повторно проверены синтаксис shell/Python, распаковка tar с `sha256sum -c`, полнота манифеста, LF, Unix-права, одинаковый результат повторной упаковки и относительные ссылки документации. Эти проверки не являются новой физической установкой или повторением ручного теста клиентов.
